# Шахматы с Юрой

«Шахматы с Юрой» — голосовой шахматный навык для Яндекс Алисы. Он создавался в
первую очередь для незрячих и слабовидящих игроков, но подходит всем, кому
удобнее играть и разбирать партии голосом.

Навык понимает естественные русские шахматные фразы, объясняет недопустимые ходы,
описывает позицию, сохраняет партии и играет с помощью Stockfish. Все обязательные
действия доступны без экрана; на устройствах с дисплеем доска показывается только
как дополнение к полному голосовому ответу.

- Сайт проекта: [yurachess.ru](https://yurachess.ru)
- Продакшн-вебхук: `https://yurachess.ru/webhooks/alice`
- Стек: Python 3.12, FastAPI, SQLAlchemy, MariaDB 11.4, `python-chess`, Stockfish

## Возможности

**Партия.** Полная игра с сохранением состояния и продолжением в новой сессии
Алисы. Уровни сложности Stockfish, выбор цвета, рокировка, превращение пешки,
корректное завершение партии и экспорт PGN.

**Голос вместо доски.** Описание позиции целиком и по клеткам, поиск фигур по
типу и цвету, ответы на вопросы «чей ход», «есть ли шах», «какие фигуры съедены»,
«какой был последний ход», «какой дебют» — дебют определяется по каталогу из
3803 позиций lichess.

**Понимание речи.** Ход можно назвать как угодно: «пешка е два е четыре», «конь
эф три», «е два е четыре», «рокировка». Если фраза допускает несколько ходов или
распознана неуверенно, навык просит уточнение и не меняет позицию. Если ход
недопустим, навык называет конкретную причину. Есть команды разбора
недопонимания: «что ты услышала», «повтори медленно», «повтори координаты по
буквам».

**Режим тренера.** Оценка позиции, ходы-кандидаты, угрозы и объяснение ходов.
Подсказки и оценки Stockfish доступны только в этом режиме: обычная партия
остаётся честной.

**Разбор сыгранной партии.** Главная ошибка, переломный момент, история ходов,
диктовка партии, экспорт PGN.

**Задачи.** Голосовые шахматные задачи из набора lichess с рейтинговыми
корзинами, показ решения и сохранение серии решений.

**Персональные настройки.** Темп речи, краткость ответов, шахматная нотация,
ориентация доски, звуки и режим следующей партии сохраняются между сессиями.

**Звук и экран.** Короткие сигналы начала, хода, шаха, мата и победы с голосовым
выключателем; изображение доски для устройств с экраном.

**Приватность.** Псевдонимная статистика: исходный идентификатор пользователя
Алисы не хранится, ключ игрока считается с серверной солью.

**Разработка без Алисы.** Консольный интерфейс прогоняет тот же сценарный слой,
что и вебхук.

## Как играть

Команды не нужно запоминать дословно: навык распознаёт разные естественные
формулировки. В любой момент можно сказать «что ты умеешь», «помощь» или
«как играть». Команды «дальше», «назад» и «сначала» помогают перемещаться по
голосовой справке.

| Задача                       | Примеры команд                                                                        |
|------------------------------|---------------------------------------------------------------------------------------|
| Начать или продолжить партию | «новая игра белыми уровень пять», «новая игра черными», «продолжить последнюю партию» |
| Сделать ход                  | «пешка е два е четыре», «конь эф три», «е два е четыре», «рокировка»                  |
| Узнать положение на доске    | «какая позиция», «что на е четыре», «где белые слоны», «чей ход», «есть ли шах»       |
| Узнать о партии              | «какой был последний ход», «какие фигуры съедены», «какой дебют», «за кого я играю»   |
| Настроить ответы             | «говори кратко», «говори медленнее», «короткая нотация», «выключи звуки»              |
| Включить помощь тренера      | «включи режим тренера», «оцени позицию», «какие ходы хорошие», «подскажи»             |
| Разобрать сыгранную партию   | «разбери партию», «где перелом», «главная ошибка», «продиктуй ходы»                   |
| Решать задачи                | «дай задачу», «задача на мат в один», «покажи решение», «какая у меня серия»          |
| Исправить недопонимание      | «что ты услышала», «повтори медленно», «повтори координаты по буквам»                 |

## Продуктовые инварианты

Эти правила определяют поведение навыка; изменение кода не должно их нарушать.
Полный список и правила разработки — в [`AGENTS.md`](AGENTS.md).

- Любое обязательное действие работает на устройстве без экрана.
- Неоднозначный или неуверенно распознанный ход никогда не применяется — навык
  переспрашивает.
- Недопустимый ход объясняется конкретно, если намерение игрока восстановимо.
- Канонический источник состояния — полная история ходов в UCI; FEN вычисляется
  из неё.
- Повторная доставка одного запроса Алисы идемпотентна и не может привести ко
  второму ходу.
- Карточка на экране дополняет ответ, но не содержит информации, которой нет в
  речи.
- Stockfish никогда не решает, допустим ли ход игрока: правила проверяет
  `python-chess`.

## Архитектура

Модульный монолит. Протокол Алисы известен только адаптерам.

| Каталог                        | Ответственность                                      |
|--------------------------------|------------------------------------------------------|
| `src/yura_chess/adapters/`     | Протокол Алисы и внешние API Яндекса                 |
| `src/yura_chess/application/`  | Сценарии приложения и маршрутизация команд           |
| `src/yura_chess/domain/`       | Состояние партии, настройки, разбор и задачи         |
| `src/yura_chess/voice/`        | Нормализация речи, распознавание и диагностика ходов |
| `src/yura_chess/storage/`      | Модели и репозитории MariaDB                         |
| `src/yura_chess/engine/`       | Ограниченный пул процессов Stockfish                 |
| `src/yura_chess/presentation/` | Голосовые ответы, PGN, доска и веб-страница          |

Состояние партии целиком лежит на сервере; в состоянии сессии Алисы хранятся
только идентификаторы, ревизия и метаданные повтора. Stockfish работает
ограниченным пулом постоянно запущенных процессов (по умолчанию два), каждый со
своим замком; поиск идёт вне event loop с жёстким дедлайном и при исчерпании
пула возвращает контролируемый ответ вместо очереди.

HTTP-поверхность: `POST /webhooks/alice`, `GET /health/live`, `GET /health/ready`
и публичные страницы сайта.

## Быстрый старт

Нужны Python 3.12, [uv](https://docs.astral.sh/uv/), Docker для MariaDB и
бинарник Stockfish.

```bash
uv sync --all-extras
cp .env.example .env
```

Поднимите базу и примените миграции:

```bash
docker compose up -d mariadb          # MariaDB 11.4 на 127.0.0.1:3307
uv run alembic upgrade head
```

Укажите в `.env` путь к Stockfish (`brew install stockfish` →
`/opt/homebrew/bin/stockfish`, `apt install stockfish` → `/usr/games/stockfish`)
и собственное значение `YURA_CHESS_IDENTITY_SALT`. Затем запустите приложение:

```bash
uv run uvicorn --factory yura_chess.main:create_app --host 127.0.0.1 --port 8000
```

Проверка готовности: `curl -s localhost:8000/health/ready`. Тот же образ, что
уезжает в продакшн, поднимается через `docker compose --profile app up`.

## Консоль без Алисы

`yura-chess-shell` прогоняет весь голосовой сценарий локально: те же команды,
тот же разбор речи, та же база. Устройство с Алисой не нужно.

```bash
uv run yura-chess-shell                                     # интерактивный режим
uv run yura-chess-shell --command "новая игра белыми" \
                        --command "пешка е два е четыре" --show-board
uv run yura-chess-shell --script scenario.txt --show-fen
```

| Флаг            | Значение                                                |
|-----------------|---------------------------------------------------------|
| `--command`     | Выполнить одну команду; можно повторять                 |
| `--script`      | Прочитать команды из UTF-8 файла                        |
| `--profile`     | Имя постоянного игрока консоли (по умолчанию `default`) |
| `--show-fen`    | Печатать FEN после игровых ответов                      |
| `--show-board`  | Печатать доску после игровых ответов                    |
| `--orientation` | `player`, `white` или `black`                           |

Выход — `exit`, `quit` или «выход».

## Конфигурация

Все переменные перечислены в [`.env.example`](.env.example) с комментариями.
Поведение навыка определяют прежде всего эти:

| Переменная                            | Назначение                                                                         |
|---------------------------------------|-------------------------------------------------------------------------------------|
| `YURA_CHESS_DATABASE_URL`             | DSN MariaDB приложения                                                             |
| `YURA_CHESS_IDENTITY_SALT`            | Серверная соль псевдонимного ключа игрока; своя на каждое окружение, не коммитится |
| `YURA_CHESS_STOCKFISH_PATH`           | Путь к бинарнику движка                                                            |
| `YURA_CHESS_ENGINE_POOL_SIZE`         | Число постоянных процессов Stockfish                                               |
| `YURA_CHESS_WEBHOOK_DEADLINE_SECONDS` | Общий дедлайн ответа Алисе                                                         |
| `YURA_CHESS_YANDEX_SKILL_ID`, `YURA_CHESS_YANDEX_OAUTH_TOKEN` | Загрузка картинок в Яндекс Диалоги; без них навык остаётся полностью голосовым |
| `YURA_CHESS_ALICE_SOUND_*`            | Свои звуки вместо встроенной библиотеки Alice sounds                               |
| `YURA_CHESS_TEST_DATABASE_URL`        | Отдельная база для интеграционных тестов; без неё они пропускаются                 |

## Тесты и проверки

Интеграционные тесты хранилища идут против настоящей MariaDB и пропускаются без
`YURA_CHESS_TEST_DATABASE_URL`. Читается он прямо из окружения, а не из `.env`,
поэтому переменную нужно экспортировать. Заведите вторую базу в том же
контейнере:

```bash
docker compose up -d mariadb
set -a && . ./.env && set +a
docker compose exec mariadb mariadb -uroot -p"$MARIADB_ROOT_PASSWORD" \
  -e "CREATE DATABASE IF NOT EXISTS yura_chess_test CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"

uv run pytest                                    # весь набор
uv run pytest tests/voice/test_move_resolver.py  # точечный прогон
```

Строка `YURA_CHESS_TEST_DATABASE_URL` из `.env.example` уже указывает на эту базу
на порту `3307`; проверьте, что пароль в ней совпадает с `MARIADB_ROOT_PASSWORD`.

Тот же набор гейтов, что и в CI ([`.github/workflows/ci.yml`](.github/workflows/ci.yml)):

```bash
uv run ruff check .
uv run ruff format --check .   # формат гейтится отдельно от линта
uv run mypy src
uv run pytest
uv run alembic upgrade head && uv run alembic check
```

Ветка, прошедшая только линтер, всё равно падает на `quality`: `ruff format
--check` — обязательный шаг. `mypy` работает в строгом режиме. Тесты с маркером
`deployed` обращаются к публичному вебхуку и не используют локальную базу.
Авторитетная база — MariaDB 11.4; тест `test_database_is_mariadb_11_4`
намеренно отвергает MySQL, ослаблять его нельзя.

## Деплой

Продакшн живёт на одном хосте: Incus-контейнер, собственная MariaDB 11.4, TLS на
хостовом nginx, приложение слушает только loopback. Деплоятся только неизменяемые
теги образа `ghcr.io/blaryxoff/yura-chess:<git-sha>`; `deploy.sh` отказывается
работать с `latest`, накатывает миграции отдельным one-shot контейнером до старта
нового кода, ждёт health-check и сам возвращает предыдущий образ при неудаче.

Рунбук и топология: [`deploy/README.md`](deploy/README.md) и
[`deploy/INFRASTRUCTURE.md`](deploy/INFRASTRUCTURE.md).

## Звуковые сигналы

Короткие варианты лежат в `artifacts/sounds/`. Начало и ход собраны из реальных
CC0-записей шахматных фигур на деревянной доске; ссылки и обработка описаны в
[`artifacts/sounds/SOURCES.md`](artifacts/sounds/SOURCES.md). В
[общем превью](artifacts/sounds/yura-chess-sounds-preview.mp3) они идут в порядке:
начало, ход, шах, мат, победа. Отдельные MP3 можно загрузить в библиотеку звуков
Яндекс Диалогов, а полученные `dialogs-upload/<skill-id>/<audio-id>.opus` указать
в переменных `YURA_CHESS_ALICE_SOUND_*`. Пока они не заданы, навык использует
встроенную библиотеку Alice sounds. Исходники воспроизводимо собираются командой
`uv run python scripts/generate_game_sounds.py --preview`.

Ответ на ход содержит два полухода, и каждый звучит отдельно: сигнал вашего хода
стоит в начале, сигнал движка — на словах «Мой ход». Поэтому шах, объявленный
вами, слышен даже когда движок его тут же отражает. Для каждой половины берётся
самый значимый сигнал (победа, мат, шах, ход), а «начало» звучит только тогда,
когда в ответе не прозвучал ни один ход. Ход, который ответ не называет —
например, при досылке отложенного ответа движка, — не озвучивается повторно.

## Данные

Каталог дебютов и набор задач импортированы из открытых данных lichess под
CC0-1.0; исходный репозиторий, ревизия и детерминированный хеш результата
записаны в `src/yura_chess/data/*.meta.json`. Пересобираются скриптами
`scripts/import_lichess_openings.py` и `scripts/import_lichess_puzzles.py`.
